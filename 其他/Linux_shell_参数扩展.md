## Shell 基础：Bash 与 Sh 的关系

在讨论参数扩展之前，有必要先理清 Bash 与 Sh 的关系。

- **Sh**（Bourne Shell）是 Unix 的原始 shell，由 AT&T 开发，是 Unix 标准的一部分。
- **Bash**（Bourne Again SHell）是 GNU 项目的产物，完全向后兼容 Bourne Shell，并在此基础上增加了大量特性。

换言之，Bash **几乎包含了 Sh 的全部功能**，并做了大幅扩展。当我们以 `sh` 名称启动 Bash 时，Bash 会进入兼容模式，限制自己只使用 POSIX 标准定义的特性。

---

## 一、POSIX Sh 的常用参数扩展

### 1.1 基础语法

参数扩展最基础的形式是 `${parameter}`，其值为 `parameter` 的替换值。花括号在以下场景中是**必须**的：参数是超过一位数字的位置参数（如 `${10}`），或参数名紧跟不应被视作其一部分的字符时。

```sh
var="hello"
echo $var          # hello
echo ${var}_world  # hello_world，花括号避免将下划线误认为变量名的一部分
```

此外，在绝大多数情况下，参数扩展都应使用双引号包裹，否则变量的值将根据 IFS 变量当前的值被分割，可能意外注入额外选项。

```sh
# 推荐写法
echo "$var"
```

### 1.2 条件扩展（POSIX 核心）

下表是 POSIX Sh 定义的四类核心条件扩展，用于处理变量为空或未定义的情况。其中**是否包含冒号**决定了检查范围：

- **带冒号**（如 `:-`）：同时检查变量**未定义**或**值为空（null）**。
- **不带冒号**（如 `-`）：仅检查变量**是否被定义**，即使变量值为空字符串也会被当作“已定义”。

| 语法 | 含义 | 示例（先设 `a=123`，再 `unset a`） |
|------|------|------|
| `${param:-word}` | 若 `param` 未定义或为空，替换为 `word`；否则替换为 `param` 的值。`param` 本身不变。 | `echo ${a:-default}` → `default` |
| `${param:=word}` | 若 `param` 未定义或为空，将 `word` 赋值给 `param`，然后替换。位置参数和特殊参数无法以此方式赋值。 | `echo ${a:=default}` → `default`，随后 `echo $a` 也为 `default` |
| `${param:?word}` | 若 `param` 未定义或为空，将 `word`（若无则显示默认消息）输出到 stderr，若非交互式 shell 则退出。 | `echo ${a:?error message}` → 输出错误并退出 |
| `${param:+word}` | 若 `param` 未定义或为空，替换为空值；否则替换为 `word`。相当于反向的条件判断。 | `echo ${a:+alt}` → 空；若 `a=123` 则输出 `alt` |

### 1.3 位置参数与特殊参数

Sh 中定义了若干特殊参数，常用于脚本传参处理：

| 特殊参数 | 含义 |
|------|------|
| `$*` | 所有位置参数，作为一个整体字符串（以 IFS 首字符连接） |
| `$@` | 所有位置参数，作为独立引用的多个单词。在双引号中每个参数保持独立 |
| `$#` | 位置参数的个数 |
| `$?` | 上一条命令的退出状态码 |
| `$$` | 当前 shell 的进程 ID |
| `$!` | 最近一个后台命令的进程 ID |
| `$-` | 当前 shell 的选项标志 |

`$*` 与 `$@` 的区别需特别注意：双引号包裹下 `"$*"` 将所有参数合并为单个字符串，而 `"$@"` 保留每个参数独立——因此 `"$@"` 是更为安全的传递所有参数的方式。

## 二、Bash 独有的参数扩展

Bash 在 POSIX Sh 的基础上，增加了一系列强大的扩展功能，使字符串处理和变量操作更加高效，常常可以避免调用 `sed`、`awk`、`grep` 等外部命令。

### 2.1 字符串长度

| 语法 | 含义 | 示例 |
|------|------|------|
| `${#var}` | 返回字符串的长度（字符数） | `var="hello"; echo ${#var}` → `5` |

### 2.2 子字符串提取（Bash 特性）

| 语法 | 含义 | 示例 |
|------|------|------|
| `${var:offset}` | 从 `offset` 位置开始到末尾 | `var="0123456"; echo ${var:3}` → `3456` |
| `${var:offset:length}` | 从 `offset` 开始，取 `length` 个字符 | `echo ${var:2:3}` → `234` |

### 2.3 模式匹配删除（Prefix / Suffix Removal）

| 语法 | 含义 | 示例（设 `file="archive.tar.gz"`） |
|------|------|------|
| `${var#pattern}` | 删除**最短匹配**的**前缀**（从左开始删除） | `echo ${file#*.}` → `tar.gz` |
| `${var##pattern}` | 删除**最长匹配**的**前缀** | `echo ${file##*.}` → `gz` |
| `${var%pattern}` | 删除**最短匹配**的**后缀**（从右开始删除） | `echo ${file%.*}` → `archive.tar` |
| `${var%%pattern}` | 删除**最长匹配**的**后缀** | `echo ${var%%.*}` → `archive` |

### 2.4 查找与替换

| 语法 | 含义 | 示例 |
|------|------|------|
| `${var/pattern/replace}` | 替换**第一个**匹配 | `text="You can be what you want to be"; echo ${text/be/do}` → `You can do what you want to be` |
| `${var//pattern/replace}` | 替换**所有**匹配 | `echo ${text//be/do}` → `You can do what you want to do` |
| `${var/#pattern/replace}` | 仅当**前缀**匹配时替换 | `echo ${text/#You/We}` → `We can be...` |
| `${var/%pattern/replace}` | 仅当**后缀**匹配时替换 | `echo ${text/%be/go}` → `...to go` |

### 2.5 大小写转换

| 语法 | 含义 | 示例 |
|------|------|------|
| `${var^}` | 首字母大写 | `name="hello"; echo ${name^}` → `Hello` |
| `${var^^}` | 全部大写 | `echo ${name^^}` → `HELLO` |
| `${var,}` | 首字母小写 | `name="Hello"; echo ${name,}` → `hello` |
| `${var,,}` | 全部小写 | `echo ${name,,}` → `hello` |

### 2.6 间接引用

| 语法 | 含义 | 示例 |
|------|------|------|
| `${!var}` | 间接引用：`var` 的值为另一个变量的名称，返回该变量的值 | `name="user"; user="Sandra"; echo ${!name}` → `Sandra` |
| `${!prefix*}` / `${!prefix@}` | 列出以 `prefix` 开头的所有变量名 | `echo ${!HO*}` 列出所有以 `HO` 开头的变量 |

### 2.7 参数变换（Bash 4+）

| 语法 | 含义 | 示例 |
|------|------|------|
| `${var@Q}` | 将输出格式化为可重用的引用形式 | `var="hello world"; echo ${var@Q}` → `'hello world'` |
| `${var@E}` | 扩展字符串中的转义序列 | – |

### 2.8 数组支持（Bash 特性）

Bash 支持索引数组和关联数组，并通过参数扩展操作数组元素：

| 语法 | 含义 | 示例 |
|------|------|------|
| `arr=(apple banana cherry)` | 定义索引数组 |  |
| `${arr[1]}` | 获取第二个元素 | `banana` |
| `${arr[@]}` | 获取所有元素 | `apple banana cherry` |
| `${#arr[@]}` | 获取数组长度 | `3` |
| `declare -A map` | 定义关联数组（Bash 4+） | `map["name"]="Alice"` |

## 三、Sh 与 Bash 参数扩展的核心差异总结

| 特性 | POSIX Sh | Bash |
|------|------|------|
| **基础语法** `$var` / `${var}` | ✓ | ✓ |
| **条件扩展** `:-`、`:=`、`:?`、`:+` | ✓ | ✓（行为一致） |
| **字符串长度** `${#var}` | ✗ | ✓ |
| **子字符串提取** `${var:offset:len}` | ✗ | ✓ |
| **前缀/后缀模式删除** `#`、`##`、`%`、`%%` | ✗（非 POSIX） | ✓ |
| **查找与替换** `/`、`//` | ✗ | ✓ |
| **大小写转换** `^`、`^^`、`,`、`,,` | ✗ | ✓ |
| **间接引用** `${!var}` | ✗ | ✓ |
| **参数变换** `${var@Q}` 等 | ✗ | ✓（Bash 4+） |
| **数组支持** | ✗ | ✓ |
| **花括号扩展** `{a..z}` | 不支持，作为普通字符处理 | ✓ |
| **进程替换** `<(cmd)` | ✗ | ✓ |
| **位置参数** `${10}` 及以上 | 需花括号 | 需花括号 |

## 四、其他关键行为差异

除参数扩展外，Sh 与 Bash 在以下方面也存在影响脚本行为的重要差异：

| 差异点 | POSIX Sh | Bash |
|------|------|------|
| **错误处理** | 出错时立即停止执行 | 出错后默认继续执行（可通过 `set -e` 调整） |
| **正则表达式** | 仅支持基本正则表达式（BRE） | 支持扩展正则表达式（ERE） |
| **内置命令** | 较少，仅满足基本需求 | 大量扩展内置命令（`echo`、`read`、`test`、`printf -v` 等） |
| **双括号测试** `[[ ]]` | 不支持 | ✓，支持更多运算符（如 `=~` 正则匹配） |
| **算术扩展** | 仅 `$(( ... ))` | 额外支持 `$[ ... ]`（已废弃）、`(( ... ))` 和 `let` |
| **历史命令扩展** | 无 | ✓ |

## 五、如何选择？

- **追求最大可移植性**：编写的脚本应仅使用 POSIX Sh 定义的参数扩展（第一部分），`#!/bin/sh` 作为 shebang。
- **使用 Bash 特定特性编写脚本**：使用 `#!/bin/bash` 作为 shebang，确保系统安装了 Bash。
- **兼容性模拟**：通过 `sh` 程序名启动 Bash 时，Bash 会进入兼容模式，禁用扩展特性，行为与 Sh 保持一致。
- **调试技巧**：Bash 中可用 `set -euo pipefail` 组合启用更严格的错误处理。

---

## 重点回顾

1. **最基本的参数扩展是 `${var}`，应始终用双引号包裹以避免分词问题。**
2. **条件扩展（`:-`、`:=`、`:?`、`:+`）是 POSIX Sh 与 Bash 共有的核心特性**，带冒号与不带冒号的区别是理解的关键。
3. **`$*` 与 `$@` 在双引号中的行为不同**——优先使用 `"$@"` 传递所有参数，它会保留每个参数的独立性，更加安全。
4. **Bash 的独有扩展（子串提取、模式删除、查找替换、大小写转换等）可以替代大量外部命令调用**，使脚本更简洁、效率更高。
5. **Bash 在大括号扩展等语法上与 Sh 不兼容**，编写需要移植的脚本时应特别注意避免使用这些特性。
