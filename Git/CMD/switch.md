`git switch` 是 Git 2.23 引入的专门用于**切换分支**的命令，替代了 `git checkout` 的部分功能。常用选项如下：
### 1️⃣ 基本切换
| 选项                | 说明                              |
| ----------------- | ------------------------------- |
| `<branch>`        | 切换到已存在的本地分支                     |
| `--detach` / `-d` | 切换到 detached HEAD 状态（基于某个提交或标签） |
### 2️⃣ 创建并切换
| 选项                                  | 说明                             |
| ----------------------------------- | ------------------------------ |
| `-c <branch>` / `--create <branch>` | 创建新分支并立即切换过去                   |
| `-C <branch>`                       | 强制创建新分支（如果已存在则重置到当前 HEAD）      |
| `-c <branch> <start-point>`         | 从指定的起点（commit/branch/tag）创建新分支 |
### 3️⃣ 处理未提交的修改
| 选项                  | 说明                           |
| ------------------- | ---------------------------- |
| `-f` / `--force`    | 强制切换，丢弃工作区和暂存区的未提交修改         |
| `--discard-changes` | 丢弃工作区修改并切换（与 `-f` 类似但更明确）    |
| `--merge`           | 将当前工作区的修改自动合并到新分支（发生冲突时阻止切换） |
### 4️⃣ 跟踪远程分支
| 选项               | 说明                                            |
| ---------------- | --------------------------------------------- |
| `--guess`        | 当本地不存在 <branch> 时，自动查找远程同名分支并创建跟踪分支（**默认开启**） |
| `--no-guess`     | 关闭自动猜测行为                                      |
| `-t` / `--track` | 创建新分支时自动设置上游跟踪（与 `-c` 结合使用）                   |
### 5️⃣ 其他高级选项
| 选项                         | 说明                           |
| -------------------------- | ---------------------------- |
| `--orphan <new-branch>`    | 创建一个孤儿分支（无父提交，历史为空）          |
| `--recurse-submodules`     | 切换时同步更新子模块                   |
| `--ignore-other-worktrees` | 允许切换已被其他 worktree 使用的分支（需谨慎） |
### 📌 常见示例
```bash
git switch main                    # 切换到已有分支 main
git switch -c feature/login        # 创建并切换到 feature/login
git switch -c fix origin/fix       # 基于远程分支创建本地分支并跟踪
git switch --detach v1.0           # 切换到标签 v1.0 的游离状态
git switch -f develop              # 强制切换（丢弃本地修改）
git switch --merge feature         # 切换时尝试合并当前修改
```
### ⚠️ 与 `git checkout` 的对比
- `git switch` 专门用于分支切换，不会处理文件级别的还原（那是 `git restore` 的职责）。
- 更安全，因为不会误把分支名当文件路径处理。
