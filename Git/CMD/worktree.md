`git worktree` 是一个非常强大的工具，它允许你在同一个本地仓库中**同时检出多个分支**到不同的目录中。这在需要同时紧急修复 Bug、对比不同分支代码、或者在不中断当前工作流的情况下进行 Code Review 时非常有用。⚠️ **同一分支不能同时被两个工作区检出**

以下是 `git worktree` 的常用选项和命令详解：
## 添加工作区
这是最常用的命令，用于创建一个新的工作区目录。
- **常规用法：**
```sh
git worktree add <路径> <分支名>
```
- **常用选项：**
    - **`-b <新分支名>`**：在创建新工作区的同时，基于指定的起点创建一个**新分支**。
		```sh
		git worktree add -b feature-xyz ../feature-dir origin/main
		```
    - **`--detach`**：可以使用 `--detach` 检出特定的 Commit。以“分离头指针”（Detached HEAD）的状态检出提交，不关联任何分支。这在只想临时查看某个历史提交（Commit）或 Tag 时非常有用。
		```sh
		git worktree add --detach ../review-dir v1.0.0
		```
## 查看 
- **`git worktree list`**：列出当前仓库关联的所有工作区。
    - 输出中会显示工作区的绝对路径、当前指向的 Commit 散列值以及所在的分支。
    - **`--porcelain`**：以机器可读的格式输出，适合写脚本时使用。
## 清理与删除命令
当你在某个工作区完成工作后，需要将其清理掉。
- **`git worktree remove <工作区路径或名称>`**：安全地删除一个工作区。
    - Git 会检查该工作区是否有未提交的修改。如果有，会拒绝删除。
    - **`-f` 或 `--force`**：强制删除工作区，即使里面有未提交的修改（**慎用**，会导致未提交的代码丢失）。
- **`git worktree prune`**：清理那些你已经手动在文件管理器里删除了目录、但 Git 记录里还残留的“孤儿”工作区信息。
## 移动与锁定命令
- **`git worktree move <旧路径> <新路径>`**：如果你想更改某个工作区的目录位置，请使用此命令，而不是直接用系统命令移动。
- **`git worktree lock <工作区>`**：锁定一个工作区，防止它因为网络驱动器断开、或者误操作被 `git worktree prune` 自动清理掉。可以使用 `--reason "说明原因"` 来添加备注。
- **`git worktree unlock <工作区>`**：解锁工作区。
