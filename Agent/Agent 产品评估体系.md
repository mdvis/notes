## 一、评估体系总览：五层金字塔模型

基于业界最新实践（包括 Anthropic 内部评估方法论、AgentBench、GAIA 等主流基准），Agent 产品评估应构建如下**分层体系**：

```
                    ┌─────────────┐
                    │  用户满意度  │  ← 终极价值层
                    ├─────────────┤
                  ┌─┤  成本 & 效率  ├─┐
                  │ ├─────────────┤ │
                ┌─┤ │  稳定性/鲁棒性│ ├─┐
                │ │ ├─────────────┤ │ │
              ┌─┤ │ │  准确率/质量  │ │ ├─┐
              │ │ │ ├─────────────┤ │ │ │
            ┌─┤ │ │ │ 任务成功率   │ │ │ ├─┐  ← 基础能力层
            │ │ │ │ ├─────────────┤ │ │ │ │
            │ │ │ │ │ 工具调用效果  │ │ │ │ │
            └─┴─┴─┴─┴─────────────┴─┴─┴─┴─┘
```

## 二、六大核心维度的详细指标设计

### 1️⃣ 任务成功率（Task Completion Rate）——最关键的北极星指标

> 科锐国际CTO刘之明确指出：**"任务完成率是Agent发展的第一关键指标"**

|子指标|定义|测量方式|参考基线|
|---|---|---|---|
|**端到端成功率**|完整达成用户目标的比例|程序化状态检查 + 人工抽检|通用任务 ≥80%，复杂任务 ≥50%|
|**部分成功率**|完成部分子任务的比例|子任务拆解后逐步验证|记录每个子任务状态|
|**首次成功率 vs 重试后成功率**|区分一次做对和多次重试后成功|记录重试次数|首次成功率 ≥70%|
|**任务耗时**|从接收指令到完成的端到端时间|自动化计时|按任务类型设定 SLA|
|**失败归因分类**|规划失败/工具失败/推理失败/超时|错误标签体系|建立帕累托分析|

**评估基准参考：**

- **AgentBench**：覆盖操作系统、数据库、Web 等 8 类环境
- **GAIA**：通用AI助手评测，三级难度递进
- **WebArena**：真实网站交互任务评测
- **UI-CUBE**：通过程序化状态检查评估 UI 操作

---

### 2️⃣ 工具调用效果（Tool Calling Effectiveness）

|子指标|定义|测量方法|
|---|---|---|
|**调用成功率**|工具调用返回预期结果的比例|模拟工具故障注入测试|
|**参数正确率**|调用时参数格式/值完全正确的比例|对比预期参数 schema|
|**工具选择准确率**|在多种可用工具中选对工具的比例|构造干扰工具场景|
|**调用效率**|完成同一任务的工具调用次数（越少越好）|与最优路径对比|
|**异常恢复能力**|工具调用失败后的降级/重试/切换策略|注入超时、报错、限流等异常|
|**多工具协同**|多个工具串联/并联调用的成功率|设计跨工具链任务|

**关键实践：**

> 数据显示 **27% 的 Agent 失败源于工具调用超时，19% 源于数据格式不匹配**。建议构建**三级恢复体系**：
> 
> ```
> 任务发起 → 执行成功? 
>   → 否 → 重试(3次) 
>     → 仍失败 → 切换备用工具 
>       → 失败 → 人工介入通知
> ```

---

### 3️⃣ 准确率/输出质量（Accuracy & Quality）

|子指标|定义|测量方法|
|---|---|---|
|**事实准确性**|输出内容与事实/知识库一致|Ground Truth 对比 + LLM-as-Judge|
|**幻觉率**|生成不存在/捏造信息的比例|知识图谱/来源追溯验证|
|**推理链质量**|中间推理步骤的逻辑正确性|逐步推理轨迹审查（白盒验证）|
|**一致性**|相同输入多次运行输出的一致性|多次运行方差分析|
|**格式合规性**|输出是否符合指定格式要求|Schema 校验|
|**安全合规性**|是否触碰安全红线|红队测试 + 安全规则引擎|

**评估方法论（参考 Anthropic 实践）：**

- **黑盒评估**：只看最终输出，适合快速回归测试
- **白盒评估**：审查中间推理轨迹（Reasoning Trace），定位根因
- **LLM-as-Judge**：用另一个 LLM 评判输出质量，适合主观质量评估
- **混合评估**：程序化检查 + 人工抽检结合

---

### 4️⃣ 稳定性/鲁棒性（Stability & Robustness）

|子指标|定义|测量方法|
|---|---|---|
|**可重复性**|相同条件下多次运行结果一致|N 次运行的标准差|
|**压力稳定性**|高并发/大数据量下的成功率变化|阶梯式压力测试|
|**边界鲁棒性**|面对模糊/对抗/异常输入的表现|对抗样本 + 模糊输入测试集|
|**长任务稳定性**|长时间/多步骤任务不衰减|长链任务测试（50+ 步骤）|
|**环境适应性**|外部依赖变化（API 版本更新等）时的表现|环境变异测试|
|**退化检测**|版本迭代后性能是否回退|自动化回归测试 + 统计显著性检验|

**核心实践：**

> Anthropic 强调：**当 Agent 进入规模化落地阶段，涉及多工具调用、复杂状态管理和海量用户场景时，没有系统化评估体系的弊端会集中爆发。** 建议建立持续运行的自动化回归测试管道（CI/CD 集成）。

---

### 5️⃣ 成本 & 效率（Cost & Efficiency）

|子指标|定义|测量方法|
|---|---|---|
|**单任务 Token 消耗**|完成单个任务的 input/output token 总量|API 调用日志统计|
|**单任务货币成本**|完成单个任务的 API 调用费用|Token × 单价计算|
|**工具调用成本**|外部 API/服务调用费用|计量计费系统|
|**单步决策延迟**|每一步推理+行动的响应时间|逐步骤计时|
|**端到端延迟**|用户感知到的总等待时间|首字节到最终结果|
|**成本效率比**|成功率 / 平均成本|综合计算|

**成本优化评估矩阵：**

```
┌─────────────────────────────────────────────┐
│           成本优化策略评估                     │
├──────────┬──────────┬──────────┬─────────────┤
│ 策略      │ 成本降幅  │ 质量影响  │ 适用场景    │
├──────────┼──────────┼──────────┼─────────────┤
│ 模型降级   │ 60-80%  │ 中-高    │ 简单任务路由  │
│ Prompt精简 │ 20-40%  │ 低-中    │ 通用场景     │
│ 缓存复用   │ 30-50%  │ 无       │ 重复性任务   │
│ 工具结果缓存│ 10-30%  │ 无-低    │ 数据变化低频  │
│ 多模型路由  │ 40-60%  │ 低       │ 混合复杂度   │
└──────────┴──────────┴──────────┴─────────────┘
```

### 6️⃣ 用户满意度（User Satisfaction）

|子指标|定义|测量方法|
|---|---|---|
|**任务完成满意度**|用户对结果的显式评分|任务结束后评分（👍/👎 + 1-5分）|
|**交互体验满意度**|对 Agent 沟通过程的评价|NPS / CSAT 问卷|
|**信任度**|用户是否信任 Agent 的输出|人工复核率（越低信任越高）|
|**放弃率**|用户在任务完成前放弃的比例|行为埋点分析|
|**人工介入率**|需要人工接管才能完成的比例|系统日志统计|
|**复购/留存**|用户是否持续使用 Agent|DAU/MAU、留存曲线|

## 三、综合评分模型

### 加权评分公式

```
Agent_Score = w₁×任务成功率 + w₂×工具效果 + w₃×准确率 
            + w₄×稳定性 + w₅×成本效率 + w₆×用户满意度

其中：Σwᵢ = 1，权重根据产品阶段动态调整
```

### 不同阶段的权重建议

|维度|MVP阶段|增长阶段|成熟阶段|
|---|---|---|---|
|任务成功率|**35%**|25%|20%|
|工具调用效果|15%|**25%**|20%|
|准确率|20%|20%|**25%**|
|稳定性|10%|15%|**20%**|
|成本效率|5%|10%|10%|
|用户满意度|15%|5%|5%|

### 三层评估节奏

|层级|频率|覆盖范围|用途|
|---|---|---|---|
|**快速冒烟测试**|每次 Prompt/代码变更|50-100 核心 Case|快速回归检测|
|**完整基准评估**|每周/每个 Release|500-2000 标准 Case|版本质量门禁|
|**深度分析评估**|每月/季度|全量 + 新场景 + 对抗测试|战略方向决策|

## 五、持续优化闭环（PDCA）

```
     Plan（规划）
        ↑              ↓
   数据驱动          实施优化
   优先级排序        （模型/Prompt/工具/架构）
        ↑              ↓
     Check（检查）←── Act（执行）
        │
   评估结果分析 → 识别瓶颈 → 归因定位
```

### 典型优化路径

1. **任务成功率低** → 分析失败归因
    
    - 规划失败 → 优化 System Prompt / 引入 ReAct/Plan-and-Execute 模式
    - 工具失败 → 优化工具描述 / 增强参数校验 / 增加重试机制
    - 推理失败 → 引入 Few-shot 示例 / CoT 引导
2. **成本过高** → 实施多模型路由
    
    - 简单任务 → 小模型（GPT-4o-mini / Claude Haiku）
    - 复杂任务 → 大模型（GPT-4o / Claude Sonnet/Opus）
    - 实施结果缓存和 Prompt 精简
3. **稳定性不足** → 工程化加固
    
    - 超时控制 + 断路器模式
    - 状态快照 + 断点恢复
    - 沙箱隔离 + 权限最小化

## 七、总结：评估体系的"七项基本原则"

> 参考 Anthropic 内部实践和业界共识

1. **隔离控制**：区分 Agent Harness 问题和模型问题，避免归因混乱
2. **专家任务**：每类测试聚焦单一能力维度，避免耦合
3. **可复现性**：确定性环境 + 种子固定，确保结果可比
4. **渐进复杂度**：从单步→多步→端到端，逐层增加难度
5. **自动化优先**：能程序化判定的不依赖人工
6. **持续运行**：评估不是一次性活动，而是持续集成的一部分
7. **数据驱动决策**：所有优化决策都应基于量化数据，而非直觉
